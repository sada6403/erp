# Mobile app decisions (Run 1)

| Date | Decision | Why |
|---|---|---|
| 2026-11-07 | Local dev uses the already-running MySQL80 service on 127.0.0.1:3306 (no Docker). | Docker is not installed; backend/.env already points at localhost. |
| 2026-11-07 | Skills copied from `.agent/skills` to `.claude/skills` and kept in sync. | Kickoff section 3. |
| 2026-11-07 | App JWTs are signed with a secret derived (HMAC) from `JWT_SECRET`, payload `portal:'app'`; refresh tokens are opaque, hashed, rotating with family reuse detection. | An app token can never validate as an admin/POS/superadmin token and no new secret has to be provisioned. |
| 2026-11-07 | `app_users.member_no` = Smart Buy `paper_reference_code` if present, else generated `NP-<n>`. Login accepts phone, member no, agent code or paper reference. | One memorable id for people who do not use phone numbers; matches the paper records. |
| 2026-11-07 | An app account is linked to a customer/agent only through trusted paths (POS invite endpoint, seed). Self-registration never links to existing POS customers by phone. | Prevents someone taking over another person's Smart Buy history by typing their phone number. |
| 2026-11-07 | Cloud `products` gained the POS-only columns (`not_for_sale`, `sale_by`, `is_manage_stock`, `enable_emi`, ...) plus `is_online` (default 1), `slug`, `gallery`. | The app needs them and the sync was silently dropping them; additive and defaulted. |
| 2026-11-07 | Variant sync fix: desktop now enqueues `product_variants` / `product_variant_stocks` / `product_attribute_values`; backend `RELATED_KEYS` extended. | Variants never reached the cloud, so app variant pickers were empty. |
| 2026-11-07 | Delivery OTP is a deterministic HMAC of the order id (customer sees it in the app; salted hash in `delivery_otp_hash`); complete is idempotent by `event_id`, wrong codes limited per order and per IP. | No plaintext OTP stored, works offline-replay safe, nothing to expire or resend. |
| 2026-11-07 | `stock_reservations` are committed at order create and released on dispatched/delivered/cancelled/returned, via a post-commit hook in `sync/push` for POS-side changes. | Stock stays held while the order is in flight and is returned if it is cancelled. |
| 2026-11-07 | Selling price is treated as tax-inclusive; only `products.discount_pct` is applied (the `discounts` table is ignored); price is locked at order time. | Matches how the POS shows prices; keeps the quote simple and auditable. |
| 2026-11-07 | Notifications are queued in `notification_jobs` and sent by `/api/app/v1/cron/notifications`; Expo push and WhatsApp Cloud API are dry-run unless their flags are set. Invite messages are click-to-chat (`wa.me`) only. | Stop-list: never send real WhatsApp/push during this run. |
| 2026-11-07 | Existing real-company products need a one-time re-push from the POS after deploy, and the new tables/columns migrate on first API hit. Both are deploy-time events and need Moni's approval. | Defaults on the new product columns are not the real values until the desktop re-syncs. |
| 2026-11-07 | `master.companies.app_key` is `CHAR(36)` (`npk_` + 32 hex), generated from Super Admin; previous key honoured for a grace period. | Mirrors the existing api_key/company_key rotation pattern. |
| 2026-11-07 | Mobile route names: only `(shop)/index` serves `/`; Smart Buy home is `/schemes` and agent home is `/deliveries` (not `/`). Role groups share one `RoleLayout` (Tabs + custom bottom bar); root-level screens (settings, join, notifications) use `Frame`. | Expo Router resolves group folders to the same URL, so three `index` files would collide. A landing redirect in the root layout sends agents/members to their home. |
| 2026-11-07 | Dev mocks are an axios adapter in `mobile/src/dev/mockAdapter.ts`, `require`d only inside `if (__DEV__ && ENV.useMocks)` in `src/api/instance.ts`; the Quick Login role buttons sit behind the same flag. | Metro folds `__DEV__` to false in release bundles; verified with `expo export` that no mock strings are in the Android bundle. |
| 2026-11-07 | Fonts (Plus Jakarta Sans, Noto Sans Tamil/Sinhala, JetBrains Mono) are bundled as .ttf in `mobile/assets/fonts`, loaded with expo-font. | Works offline from first launch, no runtime dependency on @expo-google-fonts, and Tamil/Sinhala glyphs never fall back to a clipped system font. |
| 2026-11-07 | Add-to-cart works offline; only checkout / Place order is guarded (opens the Buy-later sheet when offline or `ordering_enabled` is false). | Customers can still build a basket on a bad connection; the server quote is the only source of final prices. |
| 2026-11-07 | No coupon field and no barcode-scan button in v1.0 checkout/search. | The contracts have no coupon in `QuoteRequest`, and scanning needs expo-camera, which is not in the approved library list. |
| 2026-11-07 | Wrote a small `zodResolver` (`src/lib/zodResolver.ts`) instead of adding @hookform/resolvers; zod messages are i18n keys. | @hookform/resolvers is not in AGENTS.md section 4; this keeps validation messages translatable. |
| 2026-11-07 | Offline delivery-OTP check uses a pure-JS `sha256` (`src/lib/sha256.ts`) against `delivery_otp_hash = "salt$sha256(salt+otp)"` (matches `backend/lib/app/security.ts`). The field is not yet on `AgentDeliveryDto`, so it is read as optional (`DeliveryOfflineOtp`). | Lets the agent reject a wrong code with no signal; the server still re-verifies on upload. Needs workstream A to expose the field. |
| 2026-11-07 | Gradients are drawn as stacked colour bands (`Gradient` component). | expo-linear-gradient is not in the approved list. |
| 2026-11-07 | `mobile/.npmrc` sets `legacy-peer-deps=true`; `react-native-nitro-modules` added as the peer of react-native-mmkv v4; `@react-native/jest-preset` and ESLint 9 added as dev tools. | Expo SDK 58 peers (react-dom 19.3.1 vs react 19.3.0) fail a strict install; MMKV v4 needs nitro; jest-expo and eslint-config-expo need these versions to run. |
| 2026-11-07 | `typedRoutes` is off and `baseUrl` was removed from `mobile/tsconfig.json` (paths are relative). | TypeScript 6 deprecates baseUrl; typed routes would block the dynamic `router.push` calls used for deep links. |
| 2026-11-07 | Features outside v1.0 (draw video playback, spend wallet in shop, Join request submit, Bluetooth printing, agent cash collection) render `ComingSoon` / disabled controls when `__DEV__` is false; dev builds show a basic preview. Draw video, wallet, statement, join and delete-account screens call `usePreventScreenCapture`. | Matches the kickoff v1.0 scope; no invented data is ever shown in production. |
| 2026-11-07 | POS App Access / Online Store pages are Super Admin only (`permissions.all`), enforced in the route (`RequireSuperAdmin`), the nav (`adminOnly` "Mobile App" group) and again in every `appAccess:*` / `onlineStore:*` IPC handler. | Branch Managers must not see or reach credential and storefront controls. |
| 2026-11-07 | Invite click-to-chat URLs (which embed the temp password) stay in main-process memory (`PendingChatStore`, one-shot, 30 min TTL). The renderer only gets an opaque `dispatch_id`; `appAccess:openChat` validates `https://wa.me/<digits>` and calls `shell.openExternal`. Audit rows never contain the message. Bulk invites are a one-at-a-time queue with a manual "I pressed Send" step. | Password never reaches the UI/logs; nothing is ever sent automatically. |
| 2026-11-07 | Cloud admin calls (`GET/POST /api/app/v1/admin/app-access*`) go through new `CloudApi.appAccess*` methods from the main process with the sync key. | Sync key must never reach the renderer. |
| 2026-11-07 | App Access candidates come from local `customers` (+ `chit_members` = Smart Buy) and `agents`; they are matched to app accounts by agent code or normalised phone. "Re-send temp password" reuses the invite endpoint (new temp password, resolves pending reset requests, revokes sessions). | The list endpoint has no customer_id/agent_id; the invite endpoint is the only trusted way to issue credentials. |
| 2026-11-07 | `app_settings` rows are written with `id = setting_key` (same as backend `setSetting`); keys limited to ordering_enabled, maintenance_message, min_app_version, delivery_flat_fee, delivery_free_over, download_link. | Keeps POS and backend writes on one row per key. |
| 2026-11-07 | Orders: `orders:assignAgent` is allowed for the same roles as `orders:updateStatus` (all/employees/pos), branch-scoped, and only agents of the order's branch can be assigned. | Dispatch is a branch-level job; the new pages themselves stay admin-only. |

| 2026-11-07 | Moni approved the extra mobile libraries (nitro-modules, expo-device/constants/linking/splash-screen/system-ui/status-bar, jest/eslint/RNTL dev tools); listed in AGENTS.md section 4. | Moni's answer in chat; future runs must not ask again. |
| 2026-11-07 | POS gets a "Convert app order to invoice" action (v1.0): one invoice per app order (idempotent, links `customer_orders.invoice_id` <-> `invoices.source_order_id`), reuses the `invoices:create` core (stock, FIFO batches, sync) and takes `customer_order_items.unit_price` as the locked price; price edits need a price-edit role + reason + audit row; payment follows the order; short stock blocks conversion. | Moni's answer in chat; prevents re-pricing of app orders. |
