# POS ERP 2.11.0

Agent selection advances to gift coupon entry; Enter/Tab chooses a suggestion
and advances to payment amount. Blank coupon entry skips to payment. Suggestions
are local, debounced and bounded, exclude unavailable or another customer's
coupons, and always use final coupon validation before applying. Coupon failures
allow retry and cannot submit a bill. Exact agent codes rank first.

Keyword-enabled product lookup reuses its index without a full catalog read on
each key. Fresh matched rows still provide live prices/stock. No performance
claim is made for complete checkout or printer latency without on-site profiling.

Optional Branch Hub 0.2.0 provides terminal SQLite → Hub SQLite → branch
PostgreSQL invoice replication for up to five terminals. Transactional terminal
outbox, frozen retry payloads, terminal ownership and revision checks prevent
lost delivery intent, duplicate invoices and stale replay overwrites. Address
changes preserve terminal data/identity; new terminal invoices use its prefix.
Sync Monitor shows separate branch delivery and PostgreSQL status.

See [Windows setup and rollback](../BRANCH_POSTGRES_WINDOWS.md). PostgreSQL is a
branch billing replica, not the entire ERP database: products, stock, purchases,
users and current cloud MySQL sync retain their existing storage path. No shared
offline stock reservation or cross-terminal coupon authority is introduced.

Validation: 328 unit tests, 54 targeted SQLite/LAN/PostgreSQL integration tests
and 179 existing invoice/SmartBuy/security integration tests passed. PostgreSQL SQL was executed in the isolated PGlite PostgreSQL
engine; branch Windows service, pg driver authentication/network and production
capacity still need on-site validation. Tests create only synthetic data.
Five simultaneous terminals delivered 100 invoices with retry replay and retained
exactly 100 Hub invoice identities. Standalone Hub startup/REST/backup smoke passed.
The synthetic 500-bill SQLite transaction benchmark (10 items per bill plus payment
and branch outbox, excluding checkout computation/peripherals) measured p95 1.06 ms
on the development machine. It is not a branch hardware performance guarantee.

All new tables/indexes/triggers are additive and opt-in with branch enrollment.
No production company migration or branch-server installation was performed.
No source repository/tag publication is part of this release preparation.

Binary publication completed to both existing POS update directories. Public
HTTPS and legacy feeds advertise 2.11.0 with the verified installer checksum;
installer/blockmap returned HTTP 200. An updater probe from 2.10.3 emitted
`update-available` for 2.11.0 without downloading or installing it. Previous
installers and privately backed-up update metadata remain available for rollback.
